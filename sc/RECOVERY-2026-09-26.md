# Silent-output recovery — 2026-09-26

## Confirmed cause

`04bee29` moved the master's `Splay.ar(...)` return onto a `//` comment.
The Ndef still computed internal meter values, but no longer returned its audio.
Restoring that expression, then `tidal_restart` with `62.tidal`, restored sound;
the user confirmed the kicks were audible. No system reboot or new routing was
needed for this fix. Earlier claims that PipeWire links were broken were not
supported by the recordings (capture targets were not reliably verified).

- One plugin-owned sclang/scsynth stack; no manual sclang or loopback.
- `62.tidal`: only `bd(4,4)` at gain 0.65.
- Output capture through `s.record`: `recordings/jam-20260926-1006.wav`.
  12.544 seconds, stereo peaks 0.06491 / 0.06488, RMS 0.00863 / 0.00858.

  for channel i. Master log corrected; other surface readouts need a later audit.

## Plugin changes (require Pi reload)

- Preserve multiline SC code in a temporary file; send one-line `executeFile`
  through stdin. Readline evaluated the old wrapper's `(`, body lines and `)`
  individually. Tested the new loader against the running plugin-owned sclang:
  a leading `var`, comment and multiline block print `SC_MULTILINE_OK=42`.
- DSP reload runs in a Routine, because the installer uses `s.sync` and waits.
- Panic uses `orbit.freeSynths`, not `freeAll` on an integer node ID.
- Cleanup stops only owned process trees, including grandchildren; no delayed
  name-based `pkill`. New-version shutdown also stops SC on reload, since a new
  extension instance cannot recover the old instance's stdin pipe.
- Boot scans all FAIL lines, waits for REPL readiness, and remembers the explicit
  recovery file. Concurrent ensure requests share one boot.
- Recording fails closed if `s.record` fails: no system/microphone fallback.

Migration note: the currently loaded old plugin may leave its SC process alive
on `/reload`. Inspect ownership after the first reload and stop only that old
owned tree if necessary; never kill all sclang processes by name. The revised
cleanup applies on subsequent reloads. New-version live tools still need their
post-reload smoke test; disk tests are not a substitute for it.

## Safety

Never bridge a sink monitor back to that sink. Never interpret an unverified
`pw-record --target` recording as proof of SC output. A running synth count or
an internal meter does not prove speaker output. Keep the quiet recovery pattern
available and ask for listening confirmation after output-path changes.
