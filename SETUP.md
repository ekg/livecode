# SETUP.md — reproducing this stack on a new system

Everything in `~/livecode` and `~/pi-tidal` is in git and pushed (both private:
`git@github.com:ekg/livecode.git`, `git@github.com:ekg/pi-tidal.git`). This file is
the part that lives *outside* those repos: the system wiring that made the
machine itself, so a fresh box can be brought to the same state.

## 1. System packages

- **SuperCollider** (3.13-era) and **sc3-plugins** — the master chain and the
  routing layer use `JPverb` and `Greyhole`, which come from sc3-plugins, not
  from a quark. Missing this = silently absent reverb.
- **TidalCycles** with **ghc 9.4.x** (`tidal` + `tidal-link` or per your install)
- **pipewire-jack**; on this box scsynth only boots reliably with the loader
  path fix: `LIB=x86_64-linux-gnu pw-jack sclang` (the pi-tidal plugin sets
  this itself; if you boot by hand, use the same wrapper).
- **pi** (the coding agent) — https://github.com/earendil-works/pi-coding-agent
- python deps for the tools: `scipy numpy matplotlib` (audio_test needs scipy
  for float32 wav).

## 2. SuperCollider quarks

`SuperDirt`, `Dirt-Samples` (the classic kit banks `bd sn hh cp …` — they are
registered lazily at boot and read on first use), `Vowel`.

## 3. Startup wiring (one line, easy to forget)

`~/.config/SuperCollider/startup.scd` must contain exactly:

```supercollider
"/home/<user>/livecode/superdirt_startup.scd".load;
```

That file boots the server, starts SuperDirt on 57120, loads `~/sounds/*` and
`~/sounds/mars_symlinks/*` lazily, then runs `sc/init.scd` (the verified boot:
per-orbit chains, group/aux mixing desk, master chain, and the per-orbit audio
self-test that fails the boot by name if any link is silent — see
`sc/README.md`).

## 4. The pi plugin

`~/pi-tidal` is a local pi package; register it from the livecode project via
`.pi/settings.json` (committed):

```json
{ "packages": [ "/home/<user>/pi-tidal" ] }
```

It provides the tidal_* tools (eval, record, sc eval, restart, panic, state).
After plugin edits, reload pi; the stack is then fully owned by the plugin:
`tidal_restart` stops only its own processes, boots, requires a fresh `done`
with no FAIL stage in `sc/boot.log`, restarts the REPL, and re-sends the last
`.tidal`.

## 5. Samples

- `~/sounds/` — 100+ banks (moog, jrhodes, sprvibe, mars_* 80s palette, …) plus
  `mars_symlinks/`. NOT in git (bulk audio); bring your library.
- Default kit names (`bd sn hh cp …`) come from Dirt-Samples (quark).

## 6. Tidal

`BootTidal.hs` here is generated by `tools/sc_params.py` from `sc/params.tsv` —
the custom params (`dd*`, `verb*`, `tape`, …) are declared there. Don't edit
BootTidal.hs by hand.

## 7. What is NOT in git (by design)

- `recordings/` (2 GB of takes) and album audio (`albums/**/*.flac|mp3`) — the
  album *metadata* (cues, loudness reports, cover) is committed; audio is
  regenerable from recordings via `tools/master.py` / `make_album.py`.
- tunepile corpora: the tabs corpus (625 MB `tabs-tidal/`) is gitignored and
  regenerable from source GP files via its tools; midi corpora are in LFS.
  **NB: `~/tunepile` currently has NO git remote — it is local-only.**

## 8. Verify the install

```
tidal_status          # scsynth up, superdirt listening, repl ready
tidal_restart         # boot must reach 'done' — the self-test fires one bd
                      # per orbit and FAILs by name if anything is silent
:script 60.tidal      # lo-fi hiphop through the full graph
sc/master-meter.log   # the Ndef's own meter — should trace the rhythm
```
